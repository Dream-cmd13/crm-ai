# 产品类别独立列表页改造计划（2026-05-07）

## 1. Summary
- 目标：将现有“产品类别与产品系列设置”页面改造为“产品类别独立列表页”。
- 列表字段固定为：`名称`、`分类 ID`、`图片`、`状态`、`创建时间`、`操作`。
- 操作功能固定为：`查看`、`编辑`、`删除`、`新增`。
- 侧边栏入口文案从“产品系列”改为“产品类别”，入口 ID 保持 `product-categories` 不变。
- 创建时间使用数据库 `created_at`，前端本地化显示为 `YYYY-MM-DD HH:mm`；无值显示 `-`。

## 2. Current State Analysis
- `src/pages/ProductCategories.tsx`
  - 当前是“类别树 + 系列管理 + FAB 展示”的双栏/三栏页面。
  - 已有类别读取、保存、删除逻辑（`ba_cptype`），但页面结构不符合列表化需求。
  - 当前页面耦合了 `crm_product_series` 的管理，不符合“仅产品类别”的新范围。
- `src/lib/productRepository.ts`
  - `fetchProductCategoriesFromSupabase()` 读取 `ba_cptype`，但 `mapDbCategoryToUi()` 未映射 `created_at` 到前端对象。
  - `saveProductCategoryToSupabase()` / `deleteProductCategoryFromSupabase()` 已可复用。
- `src/types/product.ts`
  - `ProductCategory` 目前缺少 `createDate`（或 `createdAt`）字段定义，无法类型化承载创建时间显示。
- `src/components/Sidebar.tsx`
  - 资源中心存在 `id: 'product-categories'` 入口，文案为“产品系列”，与新页面语义不一致。
- `src/App.tsx`
  - `product-categories` 已接入路由与页面懒加载，文案映射也是“产品系列”；逻辑可复用，仅需文案对齐。

## 3. Proposed Changes

### 3.1 `src/types/product.ts`
- 变更内容：
  - 在 `ProductCategory` 增加可选时间字段（建议 `createDate?: string`）。
- 变更原因：
  - 让创建时间成为受类型约束的展示字段，避免在页面里使用 `any`。
- 实现方式：
  - 与现有产品 `Product.createDate` 命名保持一致，统一前端时间字段语义。

### 3.2 `src/lib/productRepository.ts`
- 变更内容：
  - 在 `mapDbCategoryToUi()` 增加 `createDate` 映射：
    - 来源：`row.created_at`
    - 归一：ISO 字符串或原始值容错为空字符串。
  - `fetchProductCategoriesFromSupabase()` 保持按 `created_at` 升序读取逻辑不变（仅复用）。
- 变更原因：
  - 列表页需要稳定读取“创建时间”字段。
- 实现方式：
  - 仅补充读取映射，不改写库表结构、不改动 SQL。

### 3.3 `src/pages/ProductCategories.tsx`
- 变更内容（重构为纯“产品类别列表页”）：
  - 删除系列相关状态与逻辑：
    - `seriesList`、`selectedSeriesId`、`editingSeries`、`refreshSeries()` 等。
    - 删除对 `fetchProductSeriesFromSupabase`、`saveProductSeriesToSupabase`、`deleteProductSeriesFromSupabase` 的依赖。
  - 页面结构调整为：
    - 顶部：标题 + 新增按钮。
    - 列表区域：表格展示 `名称`、`分类 ID`、`图片`、`状态`、`创建时间`、`操作`。
  - 列表数据来源：
    - 使用现有 `fetchProductCategoriesFromSupabase()` 拉取树结构后，前端 `flatten` 成线性列表展示。
    - 可保留层级缩进（若实现成本低）或纯平铺（本次默认平铺，避免额外视觉复杂度）。
  - 字段渲染规则：
    - 名称：文本。
    - 分类 ID：`category.id`。
    - 图片：有图显示缩略图，无图显示 `-`。
    - 状态：`1=启用`、`0=禁用`，使用标签样式。
    - 创建时间：`createDate` 本地格式化 `YYYY-MM-DD HH:mm`，无值 `-`。
  - 操作列：
    - `查看`：打开 `DetailModal` 只读模式。
    - `编辑`：打开 `DetailModal` 编辑模式，复用现有 `saveProductCategoryToSupabase()`。
    - `删除`：二次确认后调用 `deleteProductCategoryFromSupabase()`；删除成功后刷新列表。
  - 新增按钮：
    - 打开 `DetailModal` 新增模式，`id` 由后端生成（沿用现有逻辑）。
  - 弹窗字段：
    - 保留 `name`、`image`、`status`，以及已存在且业务仍需保留的 `fab.*` 字段（数据不丢失）。
    - 不再提供系列字段/区域。
- 变更原因：
  - 与需求“产品类别单独页面入口 + 列表字段 + 操作功能”完全对齐。
- 实现方式：
  - 在不新增后端接口的前提下，最大化复用仓库层现有 CRUD。

### 3.4 `src/components/Sidebar.tsx`
- 变更内容：
  - 资源中心里 `id: 'product-categories'` 的文案从“产品系列”改为“产品类别”。
- 变更原因：
  - 与页面实际功能一致，降低用户理解成本。

### 3.5 `src/App.tsx`
- 变更内容：
  - `getViewLabel` 中 `'product-categories'` 映射文案由“产品系列”改为“产品类别”。
- 变更原因：
  - 与侧边栏和页面标题统一。

## 4. Assumptions & Decisions
- 已确认决策：
  - 页面范围仅“产品类别”，不再包含产品系列管理。
  - 操作功能为“查看/编辑/删除/新增”。
  - 入口文案改为“产品类别”。
  - 创建时间采用 `created_at` 本地格式化展示。
- 实施假设：
  - `ba_cptype` 表存在 `created_at` 字段（当前查询已按该字段排序，推断成立）。
  - 删除类别时继续沿用现有行为（按现有接口能力执行删除；如有外键限制沿用当前错误提示）。
- 不在本次范围：
  - 新增产品系列独立页面。
  - 变更数据库结构或新增迁移脚本。
  - 列表分页/高级筛选（可后续迭代）。

## 5. Verification Steps
- 手工功能验证：
  - 进入侧边栏“产品类别”入口，确认打开的是独立列表页。
  - 检查列表列头依次包含：名称、分类 ID、图片、状态、创建时间、操作。
  - 新增类别：保存成功后可在列表看到新数据，ID 自动生成，状态默认生效。
  - 查看类别：可打开只读详情。
  - 编辑类别：修改后列表即时/刷新后正确显示。
  - 删除类别：确认弹窗后删除成功并从列表移除。
  - 创建时间：有值时显示 `YYYY-MM-DD HH:mm`，无值显示 `-`。
  - 状态：`1/0` 对应显示“启用/禁用”。
- 冒烟检查：
  - `product-categories` 页签标题显示“产品类别”。
  - `products` 页面及产品 CRUD 不受影响。
- 质量检查：
  - 执行 TypeScript 编译或项目 lint，确保无新增类型错误。
