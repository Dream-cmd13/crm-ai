# 线索转商机-补充资料完善计划

## Summary
- 目标：完善“线索转商机 - 补充资料”链路的数据填写与落库映射，使 `crm_opportunity` 在转化时获得更完整、可追溯的数据。
- 范围：仅覆盖“线索页转商机弹窗 + 转换落库函数”链路，不改“商机页日常新建/编辑”逻辑。
- 原则：最小补全、关键字段可填写、其余字段混合默认（关键字段给默认，其余无法推导时留空）。

## Current State Analysis
- 转化入口位于 `src/pages/Leads.tsx`，弹窗标题为“线索转商机 - 补充资料”。
- 当前弹窗字段较少，仅包含：客户名称、商机名称、联系人、联系电话、预计金额、预计成交日期、状态、负责人。
- 当前落库逻辑在 `src/lib/pushdown.ts` 的 `pushLeadToOpportunityInSupabase()`：
  - 已写入部分核心字段（如 `customer_name`、`status`、`intent_amount`、`lead_id`、`inquiry_id` 等）。
  - 未覆盖/弱覆盖本次需要补全的关键项（如 `project_manager`、`product_owner`、`opp_level` 明确输入、终端与场景信息显式补充、`attachments` 继承、`contact_id` 继承）。
- 表结构基线来自 `supabase/rebuild/init.sql`：
  - `crm_lead` 已包含 `contact_id`、`attachments`、`product_series`、`product_industry` 等字段。
  - `crm_opportunity` 已包含 `project_manager`、`product_owner`、`opp_level`、`end_customer`、`end_project`、`application_scenario`、`estimated_usage`、`attachments`、`contact_person`、`lead_id`、`inquiry_id` 等字段。

## Proposed Changes

### 1) `src/pages/Leads.tsx`
- **What**
  - 扩展“转商机补充资料”弹窗字段，新增并展示：
    - `productLine`（产品线）
    - `oppLevel`（商机等级）
    - `projectManager`（项目经理）
    - `productOwner`（产品负责人）
    - `endCustomer`（终端客户）
    - `endProject`（终端项目）
    - `applicationScenario`（应用场景）
    - `estimatedUsage`（预估用量）
  - 初始化 `conversionOpportunityData` 时补充上述字段默认值。
- **Why**
  - 在转化当下补齐关键业务信息，减少转化后再次进入商机编辑页面的补录成本。
- **How**
  - 在现有 `opportunityFields` 基础上追加字段配置（保持已有字段不删除）。
  - 默认值策略：
    - 关键流程字段：`status='跟进中'`、`oppLevel='B级'`、`expectedAmount=0`、`expectedClosingDate=当天`。
    - 非关键且不可推导字段：默认空字符串。
  - 负责人字段采用 `type: 'user'`，与当前系统用户选择控件行为一致。

### 2) `src/lib/pushdown.ts`
- **What**
  - 完善 `pushLeadToOpportunityInSupabase()` 中 `oppRow` 映射：
    - `project_manager` <- `oppData.projectManager`
    - `product_owner` <- `oppData.productOwner`
    - `opp_level` <- `oppData.oppLevel`（为空时回落 `B级`）
    - `end_customer` <- `oppData.endCustomer`
    - `end_project` <- `oppData.endProject`
    - `application_scenario` <- `oppData.applicationScenario`
    - `estimated_usage` <- `oppData.estimatedUsage`
    - `attachments` <- 优先 `source.attachments`，无则空数组
    - `contact_person` <- 优先 `oppData.contactPerson`，回落 `source.contactPerson` / `source.name`
    - `contact_id` <- `source.contactId`（若目标库无列，继续依赖现有 schema fallback 自动剔除）
  - 保持既有链路字段（`lead_id`、`inquiry_id`、`intent_amount`、`product_series`、`product_industry` 等）不回退。
- **Why**
  - 与 `crm_lead` / `crm_opportunity` 表结构对齐，确保“补充资料”不仅前端可填，而且后端真实持久化。
- **How**
  - 在 `oppRow` 构建阶段增加字段映射，不改变主流程（创建商机 -> 更新线索状态）。
  - 继续复用 `insertOpportunityWithSchemaFallback()` 兼容旧库缺列环境，避免线上因单列缺失导致整体失败。
  - 附件字段统一传数组，避免 `jsonb` 写入时类型不一致。

## Assumptions & Decisions
- 已确认范围：仅“转商机链路”，不改商机页普通新建/编辑逻辑。
- 已确认策略：最小补全字段集；关键字段有默认值，其余无法推导时保留空值。
- 已确认字段偏好：补充“产品线+商机等级+终端与场景信息+负责人拆分”。
- 已确认继承策略：转化时继承线索附件与联系人关联（`contact_person/contact_id`）。
- 数据库层暂不新增迁移：本次不改表结构，仅改前端与映射逻辑。

## Verification Steps
- 功能验证（手工）：
  - 在线索详情点击“转为商机”，确认弹窗出现新增字段且可编辑。
  - 仅填写必填项转化，验证成功并跳转商机详情。
  - 填写新增字段转化，验证商机详情对应字段显示正确。
  - 验证负责人字段在商机详情显示正常（业务员/项目经理/产品负责人）。
  - 验证线索附件在新商机中可见、可下载。
  - 验证线索联系人关联可传递（至少 `contact_person` 可见）。
- 数据验证（Supabase）：
  - 检查 `crm_opportunity` 新增商机行中以下列是否按预期写入：
    - `product_line`, `opp_level`, `project_manager`, `product_owner`
    - `end_customer`, `end_project`, `application_scenario`, `estimated_usage`
    - `attachments`, `contact_person`, `lead_id`, `inquiry_id`
- 回归验证：
  - 未填写新增字段时仍可正常转化（空值/默认值符合策略）。
  - 旧库缺列场景不因单列缺失阻断转化（schema fallback 仍生效）。
