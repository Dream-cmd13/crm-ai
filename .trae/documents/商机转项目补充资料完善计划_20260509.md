# 商机转项目-补充资料完善计划

## Summary
- 目标：为“商机转项目”增加“补充资料”步骤，确保转化前可补全关键项目信息并正确落库。
- 范围：仅改 `src/pages/Opportunities.tsx` 的“转为项目”入口及 `src/lib/pushdown.ts` 的转化写库逻辑；不改 `Projects` 页面 `new_from_opportunity` 入口。
- 既定决策：
  - 入口范围：仅商机页入口。
  - 弹窗字段：关键字段集。
  - 成功后行为：打开项目详情，并将商机状态更新为“转项目”且写入关联项目ID。

## Current State Analysis
- 现入口：`src/pages/Opportunities.tsx` 的 `handleConvertToProject()` 直接调用 `pushOpportunityToProjectInSupabase(opp)`，没有补充资料弹窗。
- 当前写库：`src/lib/pushdown.ts` 的 `pushOpportunityToProjectInSupabase(source)` 仅根据 `source` 组装最小 `projectRow`（如 `project_name/status/stage/product_line/amount`），未接收额外补充字段。
- 现有项目字段能力：`src/pages/Projects.tsx` 与 `src/lib/projectRepository.ts` 已支持较完整项目字段（类型/类别/等级/客户行动/团队等），可作为本次映射基准。
- 现有回写链路：转化成功后会回写 `crm_opportunity.status='转项目'`、`associated_project=<projectId>`，并调用客户最近联系更新逻辑。

## Proposed Changes

### 1) `src/pages/Opportunities.tsx`
- **What**
  - 新增“商机转项目 - 补充资料”弹窗状态：
    - `isConvertingToProject`
    - `conversionProjectData`
    - `conversionOpportunity`
  - 点击“转为项目”时，不再直接落库；改为：
    - 根据当前商机初始化补充资料默认值。
    - 打开 `DetailModal` 让用户补充关键字段。
  - 新增转换保存方法 `confirmConvertToProject(data)` 调用仓库层新签名并在成功后跳转项目详情。
  - 在详情页与列表页两个“转为项目”按钮统一走上述新流程。
- **Why**
  - 让“补充资料”不仅可填，而且在转化瞬间进入项目主数据，减少后续二次编辑成本。
- **How**
  - 关键字段集（弹窗字段）：
    - `projectName`（默认：`${customerName}-定制项目`）
    - `projectType`（默认：`研发型项目`）
    - `projectCategory`（默认：`定制项目`）
    - `projectLevel`（默认：沿用 `oppLevel`，无则 `B级`）
    - `stage`（默认：`需求阶段`）
    - `productLine`（默认：沿用商机 `productLine`，兜底 `其他`）
    - `status`（默认：`跟进中`）
    - `customerAction`（默认：`找货寻料`）
    - `teamPm`（映射到项目经理，默认：商机 `projectManager`）
    - `salesRep`（默认：商机 `salesRep`）
    - `productOwner`（默认：商机 `productOwner`）
    - `estimatedMassProductionTime`（默认：商机 `estimatedMassProductionDate` 或空）
  - 弹窗标题：`商机转项目 - 补充资料`。
  - 转化成功后：
    - 关闭弹窗并清理临时状态。
    - 更新本地 `opportunities` 对应记录（`status='转项目'`、`associatedProject=projectId`）。
    - `navigateTo('projects', { action: 'open_existing', id: String(projectId), refreshTs: Date.now() })`。

### 2) `src/lib/pushdown.ts`
- **What**
  - 将 `pushOpportunityToProjectInSupabase` 扩展为支持第二参数（如 `projectData`），用于承接补充资料字段。
  - 完善 `projectRow` 映射，覆盖关键字段并保持既有链路（商机回写、客户最近联系）不变。
- **Why**
  - 前端补充资料必须落到 `crm_project`，否则仅是 UI 体验改善而非数据质量改善。
- **How**
  - 新函数签名：
    - `pushOpportunityToProjectInSupabase(source: Opportunity, projectData?: any)`
  - `projectRow` 映射策略：
    - `project_name` <- `projectData.projectName`，空则 `${customerName}-项目`
    - `project_type` <- `projectData.projectType`，空则 `研发型项目`
    - `project_category` <- `projectData.projectCategory`，空则 `定制项目`
    - `project_level` <- `projectData.projectLevel`，空则 `source.oppLevel` 或 `B级`
    - `stage` <- `projectData.stage`，空则 `需求阶段`
    - `product_line` <- `projectData.productLine`，空则 `source.productLine` 归一化
    - `status` <- `projectData.status`，空则 `跟进中`
    - `customer_action` <- `projectData.customerAction`，空则 `找货寻料`
    - `sales_rep` <- `projectData.salesRep`，空则 `source.salesRep`
    - `product_owner` <- `projectData.productOwner`，空则 `source.productOwner`
    - `manager` <- `projectData.teamPm`，空则 `source.projectManager`
    - `estimated_mass_production_date` <- `projectData.estimatedMassProductionTime`，空则 `source.estimatedMassProductionDate`
    - `opp_summary` <- `source.oppSummary`
    - `intent_amount` / `amount` <- `source.intentAmount`（数值化）
    - `end_customer` / `end_project` / `application_scenario` / `estimated_usage` / `product_industry` <- 优先 `source` 对应字段
    - `opportunity_id` <- 当前商机ID（若可解析为整型）
    - `lead_id` / `inquiry_id` <- 从商机透传（若可解析）
    - `attachments` <- 商机附件数组（无则空数组）
    - `team` <- 组装 `{ sales, pm, product, quality:'', purchasing:'', fae:'' }`
  - 继续保留：
    - 项目创建成功后更新 `crm_opportunity`（状态+关联项目）。
    - `updateCustomerLastContactInSupabase(..., '商机转项目')`。

## Assumptions & Decisions
- 已确认不改 `Projects.tsx` 的 `new_from_opportunity` 路径，避免同时改两条链路造成行为不一致风险扩大。
- 已确认采用关键字段集，不做完整字段全量弹窗，控制改动面。
- 已确认转化后延续当前主流程：跳转项目详情，并完成商机状态回写。
- 数据库层不新增迁移：本次仅前端流程与映射增强，复用现有 `crm_project` 字段。

## Verification Steps
- 交互验证：
  - 在商机详情页点击“转为项目”，出现“商机转项目 - 补充资料”弹窗。
  - 在商机列表页（桌面/移动）点击“转项目”，也出现同一弹窗。
  - 弹窗默认值符合策略（项目名/类型/类别/等级/阶段/状态等）。
  - 保存后跳转到项目详情页，且可看到补充字段已写入。
- 数据验证（Supabase）：
  - 校验 `crm_project` 新行字段：`project_name/project_type/project_category/project_level/stage/product_line/status/customer_action/manager/sales_rep/product_owner/estimated_mass_production_date/opportunity_id`。
  - 校验商机关联回写：`crm_opportunity.status='转项目'` 且 `associated_project=<projectId>`。
- 回归验证：
  - 不填写部分非必填补充项时仍可成功转化（按默认/空值策略落库）。
  - 现有“直接创建项目”“项目编辑保存”等流程不受影响。
