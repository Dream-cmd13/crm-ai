# 关联记录显示编号修复计划

## Summary
- 目标：将“询盘池、线索池、商机池、项目管理”中关联记录的展示从数据库主键 ID 改为业务编号（`inquiryNo`/`leadNo`/`opportunityNo`）。
- 范围：覆盖列表页、详情页、编辑弹窗（用户已确认“全部覆盖”）。
- 回退策略：当关联记录不存在或查不到编号时，回退显示原 ID（用户已确认）。
- 非目标：不修改数据库字段结构，不改变存储逻辑（仍保存外键 ID）。

## Current State Analysis
- `src/pages/Inquiries.tsx`
  - `associatedLead` 直接渲染为 ID（详情区、列表“关联线索”列）。
  - 编辑字段 `associatedLead` 目前是普通文本输入（非下拉），无法展示“编号标签”。
  - 当前只拉取 `crm_inquiry`，没有用于“lead_id -> lead_no”的映射数据源。
- `src/pages/Leads.tsx`
  - 详情区“关联询盘”直接渲染 `selectedLead.inquiryId`（ID）。
  - `fields` 中未提供 `inquiryId` 编辑项，故“编辑弹窗中的关联询盘”当前无可展示字段；主要需修复详情展示。
- `src/pages/Opportunities.tsx`
  - 详情区“关联线索/关联询盘”直接渲染 `selectedOpp.leadId`、`selectedOpp.inquiryId`（ID）。
  - `fields` 中 `leadId`、`inquiryId` 为普通输入字段，新增/编辑弹窗展示的是 ID。
- `src/components/projects/RelatedRecords.tsx`
  - 项目“关联询盘/关联线索/关联商机”直接渲染 `inquiryId/leadId/opportunityId`（ID）。
  - 组件本身没有编号映射入参。
- `src/pages/Projects.tsx` / `src/components/projects/ProjectDetail.tsx`
  - 仅透传 `selectedProject` 的关联 ID 到 `RelatedRecords`，未提供编号映射数据。

## Proposed Changes

### 1) 统一“关联ID -> 业务编号”展示映射策略（页面内按需查询）
- 原则：
  - 数据保存仍使用 ID。
  - UI 展示优先显示业务编号；查不到时显示原 ID。
  - 跳转参数仍传 ID，避免导航/查询逻辑受影响。
- 查询方式：
  - 对当前页面所需关联 ID 做去重后，按表批量查询（`in`）。
  - 表与编号字段对应：
    - `crm_inquiry`: `id`, `inquiry_no`
    - `crm_lead`: `id`, `lead_no`
    - `crm_opportunity`: `id`, `opportunity_no`

### 2) 修改 `src/pages/Inquiries.tsx`
- 新增状态与工具函数：
  - `leadNoMap: Record<string, string>`。
  - `resolveLeadDisplay(id?: string): string`（优先 `leadNoMap[id]`，否则返回 `id` 或 `-`）。
- 新增映射加载逻辑：
  - 基于 `inquiries` 中 `associatedLead` 汇总 ID，批量查询 `crm_lead(id, lead_no)`。
  - 在 `fetchInquiries` 完成后和数据变化时自动刷新映射。
- 替换展示点：
  - 详情“关联线索”按钮文本：`associatedLead` -> `resolveLeadDisplay(associatedLead)`。
  - 列表“关联线索”列：`inq.associatedLead` -> `resolveLeadDisplay(inq.associatedLead)`。
- 编辑弹窗字段改造：
  - 将 `fields` 中 `associatedLead` 改为 `type: 'select'`。
  - `options` 使用当前可用线索集合生成 `{ value: lead.id, label: lead.leadNo || lead.id }`。
  - 保障保存值仍为 ID（`value`）。

### 3) 修改 `src/pages/Leads.tsx`
- 新增状态与工具函数：
  - `inquiryNoMap: Record<string, string>`。
  - `resolveInquiryDisplay(id?: string): string`（编号优先，缺失回退 ID）。
- 新增映射加载逻辑：
  - 基于 `leads` 中 `inquiryId` 汇总 ID，批量查询 `crm_inquiry(id, inquiry_no)`。
- 替换展示点：
  - 详情“关联询盘”按钮文本：`selectedLead.inquiryId` -> `resolveInquiryDisplay(selectedLead.inquiryId)`。
- 说明：
  - `Leads` 当前没有“关联询盘”的编辑字段，不做不存在字段的新增扩展，避免引入未要求的录入能力变更。

### 4) 修改 `src/pages/Opportunities.tsx`
- 新增状态与工具函数：
  - `leadNoMap`、`inquiryNoMap`。
  - `resolveLeadDisplay`、`resolveInquiryDisplay`。
- 新增映射加载逻辑：
  - 从 `opportunities` 汇总 `leadId/inquiryId`，分别批量查询 `crm_lead` 与 `crm_inquiry`。
- 替换展示点：
  - 详情中的“关联线索/关联询盘”文本改为编号展示（缺失回退 ID）。
- 编辑弹窗字段改造：
  - `fields` 中 `leadId`、`inquiryId` 改为 `type: 'select'`。
  - `options` 分别绑定线索/询盘编号：`{ value: id, label: no || id }`。
  - 保持保存值为 ID。

### 5) 修改 `src/pages/Projects.tsx`、`src/components/projects/ProjectDetail.tsx`、`src/components/projects/RelatedRecords.tsx`
- 在 `Projects.tsx` 中新增项目上游编号映射状态（例如 `relatedNoMap`）：
  - 针对当前 `selectedProject` 的 `inquiryId/leadId/opportunityId` 按需查询对应编号。
  - 组装为：
    - `inquiryDisplay`
    - `leadDisplay`
    - `opportunityDisplay`
  - 缺失时回退原 ID。
- 在 `ProjectDetail.tsx` 扩展 `RelatedRecords` 入参，透传上述显示文案。
- 在 `RelatedRecords.tsx`：
  - 新增可选 props：`inquiryDisplay`、`leadDisplay`、`opportunityDisplay`。
  - 渲染时展示 `*Display`，点击跳转仍传原 ID。

## Assumptions & Decisions
- 决策：仅调整展示层，不修改现有表结构、外键字段及保存逻辑。
- 决策：导航参数继续使用 ID，确保与当前 `navigateTo` + 页面按 ID 拉取的机制兼容。
- 决策：若关联记录已删除/编号为空，统一回退显示原 ID，不额外显示错误文案。
- 假设：`crm_inquiry/lead/opportunity` 的编号字段分别为 `inquiry_no`、`lead_no`、`opportunity_no`，并与当前映射函数一致。

## Verification Steps
- 手工验证（重点）：
  - 询盘池：
    - 列表“关联线索”显示线索编号。
    - 详情“关联线索”显示线索编号并可正常跳转。
    - 编辑弹窗“关联线索”下拉展示“线索编号”，保存后仍能正确关联。
  - 线索池：
    - 详情“关联询盘”显示询盘编号并可跳转。
  - 商机池：
    - 详情“关联线索/关联询盘”显示对应编号并可跳转。
    - 新建/编辑弹窗中“关联线索/关联询盘”下拉展示编号，保存后关联正确。
  - 项目管理：
    - 项目详情“关联询盘/关联线索/关联商机”显示对应编号并可跳转。
  - 回退场景：
    - 人工构造一个关联 ID 无法查到编号的数据，界面回退显示原 ID。
- 质量检查：
  - 对改动文件执行 TypeScript 诊断，确保无新增类型错误与显著告警。
