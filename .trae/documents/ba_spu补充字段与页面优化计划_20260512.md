### 3.1 数据库迁移（新增文件，不改历史 init.sql）
- 新增迁移文件：`new_version/migrations/20260512_alter_ba_spu_add_product_fields.sql`
- 迁移目标：对 `public.ba_spu` 增加以下列（均为向后兼容，避免影响存量数据；必要时提供默认值）：

  - `industry text`：所属行业
  - `eco_property text`：环保性质

  - 为 `product_no` 增加唯一约束（unique），避免重复编号。
- SQL 形态（示例，最终以实现为准）：
  - `alter table if exists public.ba_spu add column if not exists ...;`
- 说明：
  - 不修改 `supabase/rebuild/init.sql`，遵循“结构变更统一通过 `new_version/migrations` 增量迁移”的约定。

## 4. Assumptions & Decisions
- 字段命名与类型决策（本计划的默认选择）：
  - 命名：DB 采用 snake_case（`product_no/eco_property/...`），前端采用 camelCase（`productNo/ecoProperty/...`）。
  - 产品图纸：使用 `jsonb` 存储附件数组（与现有 `crm_inquiry/crm_lead/crm_project` 的 `attachments jsonb` 一致），以复用 `DetailModal` 的 `attachments` 能力。
  - 产品主图：使用 `text`，允许 URL 或 dataURL。
  - 最小起订量：`numeric(18,2)`，允许 `NULL`，前端用 `number` 输入（空值保持为空）。
  - 产品编号：`product_no` 增加数据库唯一约束（unique）。
- 非本次范围：
  - 自动编号生成规则（如需，可在后续单独补充迁移与规则）。
  - 引入 Supabase Storage 或外部对象存储（本次沿用系统已有的“URL/dataURL 入库”模式）。
