# 项目池按客户分级分类实施计划

## 一、Summary

目标：将项目按客户等级自动归入不同项目池，并在项目管理页通过 Tab 展示；同时新增项目类别字段 `projectCategory`（`定制项目`/`标准项目`），用于项目管理与筛选。

已确认决策：
- 项目池分为 3 类：`战略客户项目池`、`成长型客户项目池`、`普通客户项目池`。
- 项目类别采用新增字段：`projectCategory`，不复用 `projectType`。
- 展示入口放在 `项目管理页 Tab`。
- 项目池随客户等级自动迁移（实时计算/同步）。
- `projectCategory` 全项目必填（新增和编辑都需选择）。
- 历史项目 `projectCategory` 先保留空值，不做批量回填。

## 二、Current State Analysis

### 2.1 项目模块现状
- 页面入口：`src/pages/Projects.tsx`。
- 列表组件：`src/components/projects/ProjectList.tsx`，目前固定 Tab 为时间/状态维度（如“本周项目”“重点项目”），无客户等级项目池维度。
- 卡片组件：`src/components/projects/ProjectCard.tsx`，展示项目等级等字段，无“项目池/项目类别”展示。
- 新建/编辑项目字段定义位于 `Projects.tsx` 的 `projectFields`，目前无 `projectCategory` 字段。

### 2.2 类型与仓储层现状
- `Project` 类型定义在 `src/types/business.ts`，当前无 `projectCategory` 与 `projectPool` 字段。
- 项目仓储在 `src/lib/projectRepository.ts`，`mapDbProjectToUi/mapUiProjectToDb` 已覆盖大部分项目字段，但无项目类别映射。

### 2.3 数据层现状
- `crm_project` 表定义位于 `supabase/rebuild/init.sql`，当前无 `project_category` 字段。
- `crm_project` 已有 `customer_id`（整型外键）和 `customer_name`，可用于关联客户。
- 客户等级在 `ba_manucustinfo.level`（`战略客户`/`成长型客户`/`普通客户`），可用于项目池自动归类。
- 仓储侧已遵循 UI customerId -> DB 整型 ID 的解析模式（通过客户仓储中的解析逻辑）。

## 三、Proposed Changes

### 3.1 数据库迁移（新增项目类别字段）

文件：
- `new_version/migrations/20260509_add_project_category_and_pool_support.sql`（新增）

变更内容：
- 为 `public.crm_project` 新增列：`project_category text`（允许空，兼容历史数据）。
- 增加可选约束（建议）：
  - `check (project_category in ('定制项目','标准项目') or project_category is null)`。
- 增加列注释（可选）说明字段语义。

设计原因：
- 保持与现有结构兼容，不修改历史初始化脚本。
- 历史数据可空，避免一次性数据修复风险。

### 3.2 类型层扩展

文件：
- `src/types/business.ts`

变更内容：
- 在 `Project` 接口新增字段：
  - `projectCategory?: '定制项目' | '标准项目' | string`
  - `projectPool?: '战略客户项目池' | '成长型客户项目池' | '普通客户项目池' | string`（运行时计算字段，不要求落库）

设计原因：
- `projectCategory` 为持久化字段。
- `projectPool` 由客户等级自动计算，减少冗余存储与同步成本。

### 3.3 仓储层映射与自动归池

文件：
- `src/lib/projectRepository.ts`

变更内容：
- 在 `mapDbProjectToUi` 增加 `projectCategory: row.project_category || ''` 映射。
- 在 `mapUiProjectToDb` 增加 `project_category: project.projectCategory || null` 回写。
- 在查询项目列表时补充客户等级信息并计算 `projectPool`：
  - 方案 A（推荐）：项目查询后，按 `customer_id` 批量查询 `ba_manucustinfo(id, level)`，在内存中映射 `projectPool`。
  - 映射规则：
    - `战略客户` -> `战略客户项目池`
    - `成长型客户` -> `成长型客户项目池`
    - 其他 -> `普通客户项目池`
- 对无 `customer_id` 或查不到客户等级的数据，统一归入 `普通客户项目池`（兜底规则）。

设计原因：
- 不引入项目池冗余列，天然支持“客户等级变化 -> 项目池自动变化”。
- 通过批量查询避免 N+1 请求。

### 3.4 项目页筛选与 Tab 改造

文件：
- `src/components/projects/ProjectList.tsx`
- `src/pages/Projects.tsx`

变更内容：
- `ProjectList.tsx`
  - Tab 改为池维度优先：`全部项目`、`战略客户项目池`、`成长型客户项目池`、`普通客户项目池`。
  - 追加“项目类别”筛选控件（`全部/定制项目/标准项目`）。
- `Projects.tsx`
  - 新增状态：`projectCategoryFilter`。
  - 在 `filteredProjects` 中加入：
    - 按 `activeTab` 过滤 `projectPool`。
    - 按 `projectCategoryFilter` 过滤 `projectCategory`。
  - 新增/编辑字段 `projectFields` 加入：
    - `{ key: 'projectCategory', label: '项目类别', type: 'select', options: ['定制项目', '标准项目'], required: true }`
  - `handleCreateProject` 和 `handleSaveProject` 增加默认值与必填兜底（若无值可提示或默认 `标准项目`，以产品最终交互为准）。

设计原因：
- 以页面主入口实现，满足“项目池 Tab 展示”诉求。
- 项目类别在全项目范围可见且可筛选，满足“全项目必填”决策。

### 3.5 列表卡片展示增强（可选但建议）

文件：
- `src/components/projects/ProjectCard.tsx`

变更内容：
- 卡片新增项目类别显示（如 badge：`定制项目`/`标准项目`）。
- 可选显示项目池名称（弱化展示，避免视觉拥挤）。

设计原因：
- 降低用户进入详情前的识别成本。

## 四、Assumptions & Decisions

已锁定：
- 项目池不新增数据库列，按客户等级实时计算。
- `projectCategory` 存库，历史数据允许为空。
- 新增/编辑项目时 `projectCategory` 为必填。

实现假设：
- `crm_project.customer_id` 与 `ba_manucustinfo.id` 的关联在现网数据中总体可用。
- 客户等级取值以 `ba_manucustinfo.level` 为准，主要值为 `战略客户/成长型客户/普通客户`。
- 若出现异常等级值，按“普通客户项目池”兜底。

## 五、Verification Steps

### 5.1 数据层验证
- 执行新增迁移后，确认 `crm_project.project_category` 字段存在。
- 插入/更新项目时可正常读写 `project_category`。
- 历史项目不回填时，读取不报错（可为空）。

### 5.2 功能验证
- 新建项目必须选择 `项目类别`，保存成功后列表可见对应类别。
- 编辑已有项目可补录/修改 `项目类别`。
- 项目页 Tab 切换时：
  - `战略客户项目池` 仅显示战略客户关联项目；
  - `成长型客户项目池` 与 `普通客户项目池` 同理。
- 切换客户等级后，项目自动出现在新项目池（无需手工迁移）。
- “项目类别”筛选在各项目池中生效。

### 5.3 回归验证
- 原有搜索、负责人筛选、日期筛选仍可用。
- 项目详情、新建/编辑、删除流程不受影响。
- 从商机转项目路径（`new_from_opportunity`）可正常创建并保存项目类别。
