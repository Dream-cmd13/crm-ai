# 产品系列页面 CRUD 计划（基于 `crm_product_series`）

## 1. 目标摘要

- 在左侧菜单“资源中心”下新增“产品系列”页面入口。
- 新增独立页面完成 `crm_product_series` 的增删改查与列表展示。
- 页面字段按全字段方案实现：`series_no`、`name`、`category_id`、`description`、`fab_features`、`fab_advantages`、`fab_benefits`。
- 复用现有 Supabase 仓储模式和 `DetailModal` 交互，保持与“产品类别”页面风格一致。

## 2. 现状分析（已勘察）

- 已存在产品系列表与字段定义：
  - `supabase/rebuild/init.sql` 中存在 `public.crm_product_series`（`id` 为 `integer identity`，且有 `series_no` 字段）。
  - `new_version/supabase_tables.md` 已描述该表字段。
- 已存在仓储函数但字段映射不完整：
  - `src/lib/productRepository.ts` 已有 `fetchProductSeriesFromSupabase`、`saveProductSeriesToSupabase`、`deleteProductSeriesFromSupabase`。
  - 当前 `ProductSeries` 类型和仓储映射未覆盖 `series_no`。
- 前端尚无独立产品系列页面：
  - `src/App.tsx` 仅包含 `products`、`product-categories` 视图，无 `product-series`。
  - `src/components/Sidebar.tsx` 资源中心菜单无“产品系列”项。
- 已有可复用页面模板：
  - `src/pages/ProductCategories.tsx` 已实现“列表 + DetailModal + CRUD”结构，可作为产品系列页面实现模板。

## 3. 方案与改动清单

### 3.1 类型层：补齐产品系列字段

文件：`src/types/product.ts`

- 在 `ProductSeries` 增加 `seriesNo?: string` 字段，用于映射 `crm_product_series.series_no`。
- 保持 `id` 为 `string`（前端统一字符串 ID 展示/传递），仓储层做 DB/UI 转换。

原因：
- 现有“全字段方案”要求维护 `series_no`，类型需先对齐避免 TS 使用 `any`。

### 3.2 仓储层：完善 `series_no` 映射与写入规范

文件：`src/lib/productRepository.ts`

- `fetchProductSeriesFromSupabase`：
  - 增加 `seriesNo: row.series_no || ''` 映射。
- `saveProductSeriesToSupabase`：
  - 写入 payload 增加 `series_no: series.seriesNo || ''`。
  - 保持 `category_id` 的空值处理（空字符串转 `null`）。
  - 返回值补齐 `seriesNo`。
- 保持现有 `upsert(onConflict: 'id')` 逻辑不变，兼容新增与编辑。

原因：
- 避免页面层额外拼接字段，统一在仓储层保证 DB 字段与前端模型一致。

### 3.3 新增页面：产品系列列表 + CRUD

文件：`src/pages/ProductSeries.tsx`（新增）

- 页面能力：
  - 列表：展示 `name`、`series_no`、`category_id`、`description`、状态/时间（若无独立状态字段，则展示基础字段与操作列）。
  - 新增：打开 `DetailModal`，录入全字段。
  - 查看：详情只读。
  - 编辑：详情可编辑并保存。
  - 删除：确认后调用删除接口并刷新列表。
- 数据加载：
  - 初始并行加载 `fetchProductSeriesFromSupabase` 与 `fetchProductCategoriesFromSupabase`（用于类别下拉）。
- 表单字段（`DetailModal fields`）：
  - `seriesNo`（系列编号）
  - `name`（系列名称，必填）
  - `categoryId`（产品类别，`select`）
  - `description`（描述，`textarea`）
  - `fab.features`、`fab.advantages`、`fab.benefits`（`textarea`）
- 校验与交互：
  - 名称必填。
  - 保存成功/失败、删除成功/失败给出 toast。
  - 删除前二次确认。

原因：
- 满足“创建页面 + 增删改查 + 列表”的直接需求，并与现有管理页体验一致。

### 3.4 视图注册：新增 `product-series` 视图

文件：`src/App.tsx`

- 增加懒加载：
  - `const ProductSeries = lazy(() => import('./pages/ProductSeries'));`
- 在 `getViewLabel` 映射新增：
  - `'product-series': '产品系列'`
- 在 `renderView` 的 `switch` 新增：
  - `case 'product-series': return <ProductSeries />;`

原因：
- 让新增页面可被标签页系统正常打开与显示。

### 3.5 菜单入口：资源中心新增“产品系列”

文件：`src/components/Sidebar.tsx`

- 在“资源中心”分组中新增菜单项：
  - `{ id: 'product-series', label: '产品系列', icon: ... }`

原因：
- 与用户确认一致：入口放在“资源中心”下，和“产品资料/产品类别”并列。

### 3.6 可选一致性优化（同次实施内完成）

文件：`src/pages/Products.tsx`

- 系列下拉显示可从 `${id} - ${name}` 升级为 `${seriesNo || id} - ${name}`（若 `seriesNo` 为空则回退 `id`）。

原因：
- 新增字段后，产品页在选择系列时可更贴近业务编号语义，且不破坏旧数据。

## 4. 关键决策与假设

- 决策：菜单入口采用“资源中心新增（推荐）”。
- 决策：字段范围采用“全字段（推荐）”。
- 决策：继续沿用 `DetailModal`，不引入新表单组件。
- 假设：`crm_product_series` 表结构已在线上环境存在且与当前 `init.sql` 一致（无需本次新增 SQL 迁移）。
- 假设：`category_id` 允许为空（已由表结构 `on delete set null` 与仓储逻辑支持）。

## 5. 验证步骤（执行阶段）

1. 路由与入口验证
   - 打开系统后，在左侧“资源中心”可见“产品系列”菜单。
   - 点击后可正常打开“产品系列”页签。

2. 列表与查询验证
   - 页面首次加载可看到系列列表数据。
   - 列表字段与数据库记录一致，空值字段显示为 `-` 或空文案。

3. 新增验证
   - 新增一条包含全字段的数据并保存成功。
   - 刷新后仍可查询到该记录，字段值正确。

4. 编辑验证
   - 编辑已有系列的 `seriesNo/name/categoryId/description/fab` 任意字段并保存。
   - 列表与详情展示同步更新。

5. 删除验证
   - 删除一条系列记录后列表移除。
   - 删除失败时展示错误提示，不影响页面可继续操作。

6. 回归验证
   - `Products` 页系列下拉仍能正常加载并可选中保存产品。
   - `CaseLibrary`、`CommunicationLog` 等依赖系列查询的页面不报错。

7. 代码质量检查
   - 对修改文件执行 TS 诊断（`GetDiagnostics`）确保无新增类型报错。
