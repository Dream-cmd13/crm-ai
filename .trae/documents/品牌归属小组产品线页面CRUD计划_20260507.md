# 品牌 / 归属小组 / 产品线页面 CRUD 计划（2026-05-07）

## 1. Summary
- 目标：新增 3 个独立管理页面，分别基于 `ba_brand`（品牌）、`ba_group`（归属小组）、`ba_product_line`（产品线）。
- 功能范围：每个页面均支持列表、查看、新增、编辑、删除，并且支持关键字搜索与分页。
- 页面入口：统一放在侧边栏“资源中心”分组。
- 产品线展示：`ba_product_line` 采用树形层级列表（按 `parent_id` 缩进展示）。
- 字段范围：仅实现表基础字段，不扩展额外业务字段。

## 2. Current State Analysis（已勘察）
- 数据库与文档现状
  - `supabase/rebuild/init.sql` 已存在 `ba_brand`、`ba_group`、`ba_product_line` 三张表，字段满足本次 CRUD 需求。
  - `new_version/supabase_tables.md` 已有三张表定义说明：
    - `ba_brand`：`id`、`name`、`status`、`created_at`、`updated_at`
    - `ba_group`：`id`、`name`、`manager`、`created_at`、`updated_at`
    - `ba_product_line`：`id`、`parent_id`、`name`、`manager`、`created_at`、`updated_at`
- 前端现状
  - `src/lib/productRepository.ts` 仅有 `fetchBrandsFromSupabase`（读取 `ba_brand` 选项）能力，缺少品牌/归属小组/产品线三类完整 CRUD 仓储函数。
  - `src/pages` 下无品牌、归属小组、产品线独立管理页面。
  - `src/App.tsx` 和 `src/components/Sidebar.tsx` 尚无这三个页面的视图映射与菜单入口。
  - 现有 `ProductCategories.tsx`、`ProductSpu.tsx`、`ProductSeries.tsx` 已提供可复用的“列表 + DetailModal + CRUD”交互模板。

## 3. Proposed Changes

### 3.1 类型定义补齐
- 文件：`src/types/product.ts`
- 改动内容（What）
  - 新增 `Brand` 类型：`id`、`name`、`status`、`createDate`。
  - 新增 `Group` 类型：`id`、`name`、`manager`、`createDate`。
  - 新增 `ProductLine` 类型：`id`、`parentId`、`name`、`manager`、`createDate`、`children`。
- 原因（Why）
  - 为 3 个页面和仓储函数提供稳定类型边界，避免大量 `any`。
- 实现方式（How）
  - 参照现有 `ProductCategory`/`ProductSpu` 类型风格，UI 层统一使用字符串 ID；仓储层负责数值转换。

### 3.2 仓储层新增三类主数据 CRUD
- 文件：`src/lib/productRepository.ts`
- 改动内容（What）
  - 新增品牌仓储函数：
    - `fetchBrandListFromSupabase(keyword?, page?, pageSize?)`
    - `saveBrandToSupabase(brand)`
    - `deleteBrandFromSupabase(id)`
  - 新增归属小组仓储函数：
    - `fetchGroupListFromSupabase(keyword?, page?, pageSize?)`
    - `saveGroupToSupabase(group)`
    - `deleteGroupFromSupabase(id)`
  - 新增产品线仓储函数：
    - `fetchProductLineListFromSupabase(keyword?, page?, pageSize?)`
    - `saveProductLineToSupabase(line)`
    - `deleteProductLineFromSupabase(id)`
  - 增加产品线树构建工具（基于 `parent_id` -> `children`）。
  - 分页规则统一：默认每页 20，支持 20/50/100。
- 原因（Why）
  - 当前仓储层无法直接支撑页面级搜索+分页+CRUD。
- 实现方式（How）
  - 列表查询使用 Supabase `ilike`（按 `name` 模糊搜索）+ `range` 分页，并返回总数用于分页控件。
  - 保存采用“空 ID 走 insert，有 ID 走 update/upsert”的一致策略。
  - 对 `id/parent_id/status` 做显式数值归一化，避免字符串直接写入整数字段。

### 3.3 新增品牌管理页面
- 文件：`src/pages/Brands.tsx`（新增）
- 改动内容（What）
  - 页面能力：列表、搜索、新增、查看、编辑、删除、分页。
  - 列表列：品牌名称、品牌ID、状态、创建时间、操作。
  - 表单字段：`name`（必填）、`status`（启用/禁用）。
- 原因（Why）
  - 满足 `ba_brand` 独立页面管理诉求，并与现有资源中心页面交互一致。
- 实现方式（How）
  - 复用 `DetailModal` 与现有列表样式。
  - 搜索词更新时重置页码到第 1 页；分页切换重新拉取列表。

### 3.4 新增归属小组管理页面
- 文件：`src/pages/Groups.tsx`（新增）
- 改动内容（What）
  - 页面能力：列表、搜索、新增、查看、编辑、删除、分页。
  - 列表列：小组名称、小组ID、负责人、创建时间、操作。
  - 表单字段：`name`（必填）、`manager`。
- 原因（Why）
  - 满足 `ba_group` 独立页面管理诉求，支撑主数据维护。
- 实现方式（How）
  - 与品牌页保持同构实现，降低维护成本。

### 3.5 新增产品线管理页面（树形）
- 文件：`src/pages/ProductLines.tsx`（新增）
- 改动内容（What）
  - 页面能力：列表、搜索、新增、查看、编辑、删除、分页。
  - 列表展示：树形缩进显示父子产品线；显示产品线ID、名称、负责人、父级、创建时间、操作。
  - 表单字段：`name`（必填）、`parentId`（可选下拉）、`manager`。
- 原因（Why）
  - `ba_product_line` 自带层级关系，需要树形表达保证可读性与维护效率。
- 实现方式（How）
  - 查询时先取当前页数据并构建树；编辑时父级下拉使用“`id - name`”格式。
  - 保存时阻止 `parentId === id` 的自引用。

### 3.6 导航与视图注册
- 文件：`src/App.tsx`
- 改动内容（What）
  - 新增 3 个页面懒加载：`Brands`、`Groups`、`ProductLines`。
  - 在 `getViewLabel` 增加视图文案：
    - `brands` -> 品牌管理
    - `groups` -> 归属小组
    - `product-lines` -> 产品线
  - 在 `renderView` 增加 3 个 `case`。
- 原因（Why）
  - 让新页面被标签页体系正确加载、展示和切换。
- 实现方式（How）
  - 复用现有 `lazy + Suspense + tab` 架构，不改动导航主机制。

### 3.7 侧边栏新增资源中心入口
- 文件：`src/components/Sidebar.tsx`
- 改动内容（What）
  - 在“资源中心”增加菜单项：
    - 品牌管理（`brands`）
    - 归属小组（`groups`）
    - 产品线（`product-lines`）
- 原因（Why）
  - 与你确认的一致：入口统一放在资源中心。
- 实现方式（How）
  - 沿用现有菜单结构与图标体系，不调整分组逻辑。

### 3.8（可选）产品页下拉数据一致性增强
- 文件：`src/pages/ProductSpu.tsx`（可选联动）
- 改动内容（What）
  - 品牌下拉和品牌展示继续复用 `ba_brand`，新增品牌后在该页可即时可见。
- 原因（Why）
  - 避免新增主数据页后出现“可维护但不可消费”的断层。
- 实现方式（How）

- 已确认决策

  - 三个页面入口放“资源中心”。

  - 字段仅按三张表基础字段。
  - 产品线采用树形层级列表。

  - 现有 `DetailModal` 可承载上述字段配置和保存回调。
  - 当前项目允许继续采用前端直连 Supabase 的仓储模式。
