# 样品单字段完善与迁移计划

## Summary
- 目标：按你提供的样品单主表/细表字段规范，完善 `new_version/supabase_tables.md` 中 `crm_sample_order` 与 `crm_sample_order_item` 的字段定义，并在 `new_version/migrations` 新增迁移 SQL。
- 核心决策：
  - `status` 使用 6 个值：`leader_reject`、`wait_leader_examine`、`completed`、`stay_follow_up`、`cancellation`、`closure`。
  - 旧字段保留并新增新字段（兼容优先）。
  - 字段存在性核对口径：以仓库 SQL（`supabase/rebuild/init.sql` + `new_version/migrations`）为准。
  - `id` 改造范围：主表+细表都改为 `int` 自增主键。
  - 细表关联：保留 `sample_order_id` 作为主关联外键，同时新增业务字段 `sample_no`。

## Current State Analysis
- 当前文档 `new_version/supabase_tables.md` 中：
  - `crm_sample_order.id` 为 `text primary key`。
  - `crm_sample_order_item.id` 为 `text primary key`，`sample_order_id` 为 `text` 外键。
  - 主表缺少你要求的多数字段（如业务员、跟单员、收件地址、驳回信息、申请附件等）。
  - 细表缺少你要求字段（客户物料号/名、客户交期等）。
- 当前数据库基线 `supabase/rebuild/init.sql` 与文档一致，仍是旧结构（`text` 主键体系）。
- `new_version/migrations` 目前仅有采购报价相关迁移（`20260428_01_add_purchase_quotation_tables.sql`），尚无样品单结构升级迁移。

## Proposed Changes

### 1) 更新文档：`new_version/supabase_tables.md`
- 位置：`crm_sample_order` 与 `crm_sample_order_item` 两个章节。
- 变更策略：保留已存在字段，不重复创建；补充缺失字段并明确约束/默认值/含义。
- 主表（`crm_sample_order`）计划字段：
  - 主键：`id int not null unsigned auto_increment primary key`（文档写法与当前项目风格保持一致）。
  - 业务基础：`sample_no`、`customer_name`、`sales_rep`、`merchandiser`、`applicant`。
  - 制单信息：`created_by`、`created_time`（并保留系统审计字段 `created_at/updated_at`）。
  - 状态：`status`（6 值枚举语义说明）。
  - 联系与地址：`recipient`、`mobile_phone`、`province`、`city`、`district`、`detail_address`。
  - 审核与驳回：`reject_reason`、`reject_time`。
  - 业务关联：`project_id`（关联项目）。
  - 金额：`total_amount`（保留 `tax_included_total_amount`、`tax_excluded_total_amount`）。
  - 申请信息：`sample_application_note`、`application_attachments`（推荐 `jsonb`）。
  - 保留兼容字段：`customer_id`、`project_name`、`audit_status`、`created_at`、`updated_at`。
- 细表（`crm_sample_order_item`）计划字段：
  - 主键：`id int not null unsigned auto_increment primary key`。
  - 关联键：`sample_order_id int not null references crm_sample_order(id) on delete cascade`（保留为主关联）。
  - 业务字段：`sample_no`、`material_no`、`material_name`、`quantity`、`unit_price`、`line_total`、`customer_material_no`、`customer_material_name`、`customer_due_date`。
  - 兼容保留：`product_id`、`product_name`、历史税价字段、`created_at`、`updated_at`。
- 增补 ENUM 说明章节：
  - 新增 `crm_sample_order_status_enum` 及 6 个值说明（中文语义与流转说明）。

### 2) 新增迁移：`new_version/migrations/20260428_02_upgrade_sample_order_schema.sql`
- 文件风格：沿用现有迁移模板（`begin; ... commit;`、索引、触发器、RLS）。
- 迁移步骤（执行顺序）：
  1. 创建状态枚举类型（不存在才创建）：`crm_sample_order_status_enum`。
  2. 主表 `crm_sample_order` 结构升级：
     - 新增临时整型列（如 `id_new integer generated by default as identity`）。
     - 回填并建立唯一约束，替换主键到新整型列。
     - 将原 `id` 重命名为 `id_legacy`（保留兼容追溯），`id_new` 重命名为 `id`。
     - 新增缺失业务字段（`if not exists`）。
     - `status` 列转换为枚举类型（含旧值到新枚举的映射，无法映射值兜底到 `stay_follow_up`）。
     - 补充 `id > 0` check 约束（模拟 unsigned）。
  3. 细表 `crm_sample_order_item` 结构升级：
     - 同样将 `id` 改为整型自增主键（保留 `id_legacy`）。
     - 新增 `sample_order_id_new integer`，按旧 `sample_order_id(text)` 与主表 `id_legacy` 关联回填。
     - 旧外键切换为新外键：`sample_order_id` 改为 `integer` 并重建 FK。
     - 新增细表缺失业务字段（`sample_no`、`material_name`、`unit_price`、`line_total`、`customer_material_no`、`customer_material_name`、`customer_due_date` 等）。
     - 补充 `id > 0` check 约束。
  4. 索引补充（按查询需求）：
     - 主表：`sample_no`、`status`、`customer_id`（若已存在则跳过）。
     - 细表：`sample_order_id`、`sample_no`。
  5. 触发器与 RLS：
     - 若 `app_meta.attach_updated_at_trigger(text)` 存在则挂载两表 `updated_at` 触发器。
     - 若 `app_meta.apply_open_policies(text)` 存在则调用；否则按现有开放策略创建/更新策略。

### 3) 兼容与风险控制
- 由于主键从 `text` 切换为 `int`，迁移中保留 `id_legacy`，避免历史文本 ID 丢失。
- 细表关联迁移依赖 `id_legacy` 映射，需在同一事务中先主表后细表执行。
- 新增字段全部使用 `add column if not exists`，避免重复执行报错。
- 对旧 `status` 文本值做显式映射，避免转换失败中断事务。

## Assumptions & Decisions
- 不删除既有金额/审核字段，遵循“保留并新增”。
- 细表主关联继续使用 `sample_order_id` 外键到主表 `id(int)`。
- `application_attachments` 采用 `jsonb` 保存附件结构（URL/名称/类型等）。
- “数据库字段是否存在”仅按仓库 SQL 口径核对，不连接线上 Supabase 实例。
- 文档中的“unsigned/auto_increment”继续沿用项目既有描述风格；实际 PostgreSQL 通过 `identity + check(id > 0)`实现。
