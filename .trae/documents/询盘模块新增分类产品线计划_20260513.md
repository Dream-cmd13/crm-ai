# 询盘模块新增分类产品线实施计划

## Summary

- 目标：在询盘模块新增“分类产品线”字段，并按 `1=IO`、`5=线束`、`2=工业`、`6=新能源`、`4=接插件`、`7=原厂`、`3=加工` 进行前端显示映射；数据库仅存数字 key。
- 范围：覆盖询盘新增、编辑、详情、列表、移动端卡片、数据库保存/读取，以及“询盘转线索”链路；线索侧同步新增同类字段并沿用相同 key/value 映射。
- 不在本次范围：不继续向商机/项目新增该字段；不修改历史初始化 SQL，SQL 变更仅通过 `new_version/migrations` 新增迁移文件落实。

## Current State Analysis

### 现有询盘实现

- `src/pages/Inquiries.tsx`
  - 询盘读取通过 `mapDbInquiryToUi()` 将 `crm_inquiry` 行映射到前端 `Inquiry` 对象。
  - 保存通过 `handleSave()` 和 `persistInquiryStatusUpdate()` 组装 `dbData` 写入 `crm_inquiry`。
  - 新增/编辑弹窗字段、详情展示、桌面列表、移动卡片都集中在同一文件中维护。
  - 当前已有 `productSeries` 与旧兼容字段 `category`，但没有“分类产品线”这种“key 存库、label 展示”的枚举字段。

### 现有线索实现

- `src/pages/Leads.tsx`
  - 线索读取通过 `mapDbLeadToUi()` 映射 `crm_lead`。
  - 保存通过新建/编辑逻辑写入 `crm_lead`。
  - 当前存在 `productCategory`（旧兼容文本字段）与 `productSeries`，没有对应的数字 key 字段。

### 现有转化链路

- `src/lib/pushdown.ts`
  - `pushInquiryToLeadInSupabase()` 直接从 `Inquiry` 组装 `leadRow` 写入 `crm_lead`。
  - 如果不改这里，即使询盘页面新增字段，转线索时也不会自动同步到线索侧。

### 现有数据库与迁移约定

- `supabase/rebuild/init.sql`
  - 当前 `crm_inquiry`、`crm_lead` 均未包含“分类产品线”字段。
  - 项目已有明确约定：不直接改历史初始化脚本。
- `new_version/migrations`
  - 当前已有按日期命名的增量迁移文件，适合新增本次字段。
- `new_version/supabase_tables.md`
  - 当前表结构文档未记录本次字段，实施后应同步补充。

## Assumptions & Decisions

- 前端字段命名统一为 `classificationProductLine`。
- 数据库列命名统一为 `classification_product_line`。
- 数据库存储类型使用 `integer`，允许为空；前端表单值使用字符串 key（`'1' | '2' | '3' | '4' | '5' | '6' | '7'`），保存前转换为整数，读取后转回字符串供表单与显示复用。
- 枚举映射固定为：
  - `1 -> IO`
  - `5 -> 线束`
  - `2 -> 工业`
  - `6 -> 新能源`
  - `4 -> 接插件`
  - `7 -> 原厂`
  - `3 -> 加工`
- 线索同步策略：线索表也新增 `classification_product_line`，不复用旧文本字段 `product_category` 作为本字段的最终存储位。
- 转商机链路本次不承接该字段；旧字段 `category` / `productCategory` 保持兼容，不做替换式改造。
- 历史数据不强制回填；已有记录该字段为空时，前端显示 `-`。

## Proposed Changes

### 1. 新增共享枚举工具

- 新增文件：`src/lib/classificationProductLine.ts`
- 内容：
  - 定义共享 options 数组，供 `DetailModal` 下拉直接使用：`[{ value: '1', label: 'IO' }, ...]`
  - 定义 key -> label 映射表
  - 提供读取/保存辅助方法，例如：
    - `normalizeClassificationProductLineKey(value)`：将数据库整数/未知输入统一转为前端字符串 key 或空值
    - `toClassificationProductLineDbValue(value)`：将前端字符串 key 转为数据库整数或 `null`
    - `getClassificationProductLineLabel(value)`：将 key 转为中文展示值
- 原因：
  - `Inquiries.tsx`、`Leads.tsx`、`pushdown.ts` 都需要同一套映射，集中维护可避免枚举漂移。

### 2. 扩展业务类型定义

- 修改文件：`src/types/business.ts`
- 内容：
  - 为 `Inquiry` 增加 `classificationProductLine?: string`
  - 为 `Lead` 增加 `classificationProductLine?: string`
- 原因：
  - 使询盘页面、线索页面、转化链路都能以类型安全方式访问该字段。

### 3. 新增数据库迁移

- 新增文件：`new_version/migrations/20260513_add_inquiry_lead_classification_product_line.sql`
- 内容：
  - 为 `crm_inquiry` 增加 `classification_product_line integer`
  - 为 `crm_lead` 增加 `classification_product_line integer`
  - 为两个字段增加允许值校验，限制为 `1,2,3,4,5,6,7`
  - 不设置默认值，不做历史回填
- 原因：
  - 满足“数据库存 key（数字）”要求
  - 与用户既有 SQL 变更约定一致，只新增迁移，不碰历史初始化脚本

### 4. 更新表结构文档

- 修改文件：`new_version/supabase_tables.md`
- 内容：
  - 在 `crm_inquiry`、`crm_lead` 字段说明中补充 `classification_product_line`
  - 备注其语义为“分类产品线（存数字 key，前端映射显示）”
- 原因：
  - 保持文档与实际结构一致，方便后续排查与开发。

### 5. 改造询盘页面字段流转

- 修改文件：`src/pages/Inquiries.tsx`
- 具体改动：
  - 在顶部引入共享枚举工具与下拉 options。
  - 在 `mapDbInquiryToUi()` 中把 `row.classification_product_line` 映射为 `classificationProductLine` 字符串 key。
  - 在 `handleSave()` 的 `dbData` 中写入 `classification_product_line` 整数值。
  - 在 `persistInquiryStatusUpdate()` 中一并保留/回写 `classification_product_line`，避免关闭询盘等状态操作覆盖该字段。
  - 在 `fields` 中新增 `classificationProductLine` 下拉项，建议放在 `productSeries` 后，label 使用“分类产品线”。
  - `addFields` 与 `editFields` 自动纳入该字段。
  - 在详情页“基本信息”中新增该字段展示，使用 label 展示而不是 key。
  - 在桌面列表与移动卡片中新增该列/信息项，统一显示 label。
- 原因：
  - 询盘页面的读、写、展示目前都集中在该文件，需一次性补齐全链路以免出现“可编辑但不可显示”或“显示正确但保存丢失”的问题。

### 6. 改造线索页面字段流转

- 修改文件：`src/pages/Leads.tsx`
- 具体改动：
  - 引入同一套共享枚举工具。
  - 在 `mapDbLeadToUi()` 中映射 `row.classification_product_line` -> `classificationProductLine`。
  - 在线索新增/编辑保存的 `dbData` 中写入 `classification_product_line`。
  - 在线索字段配置 `fields` 中新增“分类产品线”下拉，建议放在 `productSeries` 后、`productCategory` 前。
  - 在线索详情与列表增加该字段展示，统一显示 label。
  - 保留 `productCategory` 作为旧兼容字段，不与本次新字段合并。
- 原因：
  - 用户已确认“询盘转线索时线索也新增 key 字段”，因此线索页面必须具备独立读取、编辑、展示能力。

### 7. 改造询盘转线索同步逻辑

- 修改文件：`src/lib/pushdown.ts`
- 具体改动：
  - 引入共享转换工具。
  - 在 `pushInquiryToLeadInSupabase()` 组装 `leadRow` 时，新增 `classification_product_line`，来源为 `leadData?.classificationProductLine ?? source.classificationProductLine`
  - 不改变 `product_category` 现有赋值逻辑，避免影响旧链路兼容行为。
- 原因：
  - 询盘转线索是绕过 `Leads.tsx` 新建表单直接写库的入口，不改这里会导致同步失效。
