# 产品资料详情页化改造计划（ba_cpinfo / ba_cptype）

## 一、Summary
- 目标：将“产品资料（`ba_cpinfo`）+ 产品类别（`ba_cptype`）”的详情查看从弹框改为系统内新标签页展示，并将编辑能力同步迁移到页面内完成。
- 范围：
  - 包含：`Products` 页面中的产品查看/编辑；`ProductCategories` 页面中的类别查看/编辑。
  - 不包含：`ProductSpu`、`ProductSeries` 本轮改造。
- 交互决策：
  - 打开方式采用系统内 `navigateTo` 新标签页（非浏览器新窗口）。
  - 详情页保留现有全字段展示，不做字段裁剪。
  - 编辑不再通过详情弹框完成，改为详情页内编辑态。

## 二、Current State Analysis

### 2.1 产品资料页（现状）
- 文件：`src/pages/Products.tsx`
- 数据来源：`fetchProductsFromSupabase()`（`ba_cpinfo`）与 `fetchProductCategoriesFromSupabase()`（`ba_cptype`）。
- 现有行为：
  - 列表点击物料编号或移动端“详情”按钮：`setSelectedProduct(product)`。
  - 通过 `DetailModal` 展示产品详情（只读）。
  - 通过 `DetailModal` 承载新增/编辑产品。
- 问题：详情与编辑均依赖弹框，不符合“新开页面展示详情/编辑”的目标。

### 2.2 产品类别页（现状）
- 文件：`src/pages/ProductCategories.tsx`
- 数据来源：`fetchProductCategoriesFromSupabase()`（`ba_cptype` 树结构）。
- 现有行为：
  - “查看/编辑/新增”均通过 `DetailModal` 完成。
- 问题：查看详情仍为弹框；编辑流程也在弹框内。

### 2.3 应用导航机制（可复用）
- 文件：`src/App.tsx`
- 当前已支持 `navigateTo(view, params)` + 顶部 Tab 打开模式。
- `buildTabKey()` 会优先读取 `params.id` 生成稳定 tab key，适合详情页按记录 ID 打开。
- 结论：本次应沿用该机制，为产品/类别新增 view 类型并接入 `renderView`。

### 2.4 数据访问层（现状）
- 文件：`src/lib/productRepository.ts`
- 已有：
  - `fetchProductsFromSupabase` / `saveProductToSupabase` / `deleteProductFromSupabase`
  - `fetchProductCategoriesFromSupabase` / `saveProductCategoryToSupabase` / `deleteProductCategoryFromSupabase`
- 缺口：缺少按 ID 获取单条产品/类别的方法，不利于详情页直开（如刷新后仅依赖参数 ID）。

## 三、Proposed Changes

### 3.1 路由与标签接入（`src/App.tsx`）
- 新增两个视图标识：
  - `product-detail`
  - `product-category-detail`
- 变更点：
  - `getViewLabel`：加入两种详情页标题映射（支持携带名称时显示“产品详情 · xxx / 产品类别详情 · xxx”）。
  - `renderView`：接入新详情页组件并透传 `viewParams/navigateTo/goBack`。
- 目的：让详情页以系统内新 Tab 方式打开，与现有项目/客户详情交互一致。

### 3.2 数据层补充按 ID 查询（`src/lib/productRepository.ts`）
- 新增方法：
  - `fetchProductByIdFromSupabase(id: string): Promise<Product | null>`
  - `fetchProductCategoryByIdFromSupabase(id: string): Promise<ProductCategory | null>`
- 实现约束：
  - 继续遵循现有 ID 规范（数据库整型 ID，UI 侧字符串化）。
  - 复用既有映射函数（`mapDbProductToUi` / `mapDbCategoryToUi`），避免字段口径不一致。
- 目的：支持详情页仅依赖 `viewParams.id` 独立加载数据，并兼容刷新/深链打开。

### 3.3 新增产品详情页面（`src/pages/ProductDetail.tsx`）
- 页面职责：
  - 根据 `viewParams.id` 加载产品详情（来自 `ba_cpinfo`）。
  - 展示完整字段（沿用 `Products.tsx` 当前全字段策略，含分类属性扩展字段）。
  - 在页面内提供查看态/编辑态切换与保存。
- 关键交互：
  - 顶部面包屑：`产品资料 / {物料名称或编号}`；返回按钮回到产品列表 tab（或调用 `goBack`）。
  - 编辑按钮进入编辑态；保存调用 `saveProductToSupabase`。
  - 保存成功后刷新当前记录并更新标题信息（例如名称变化）。
- 依赖数据：
  - 产品详情：`fetchProductByIdFromSupabase`
  - 类别树：`fetchProductCategoriesFromSupabase`（用于类别下拉和属性字段计算）
  - 系列：`fetchProductSeriesFromSupabase`

### 3.4 新增产品类别详情页面（`src/pages/ProductCategoryDetail.tsx`）
- 页面职责：
  - 根据 `viewParams.id` 加载类别详情（来自 `ba_cptype`）。
  - 展示完整类别字段（名称、状态、图片、FAB 三段、父子关系信息）。
  - 页面内提供查看态/编辑态切换与保存。
- 关键交互：
  - 顶部面包屑：`产品类别 / {类别名称}`。
  - 编辑态保存调用 `saveProductCategoryToSupabase`。
  - 保存成功后刷新单条数据并保留当前 tab。
- 数据处理：
  - 详情可先按 ID 查询；若需父级名称展示，可结合全量类别树做映射。

### 3.5 列表页改造为“页面跳转查看/编辑”

#### 3.5.1 `src/pages/Products.tsx`
- 将以下入口改为 `navigateTo('product-detail', { id, title/name, mode })`：
  - PC 列表物料编号点击（当前为 `setSelectedProduct`）
  - 移动端“详情”按钮
- 编辑迁移：
  - 列表页不再打开产品查看/编辑 `DetailModal`。
  - 可增加“编辑”入口（或将当前详情入口携带 `mode: 'edit'`）直接打开详情页编辑态。
- 保留：
  - 新增产品可先保持原弹框（本轮用户诉求集中在查看/编辑已有记录页化）。
  - 类别侧栏新增/编辑子类弹框可暂保留（不属于“产品类别列表详情查看”主路径）。

#### 3.5.2 `src/pages/ProductCategories.tsx`
- 将“查看”“编辑”按钮改为：
  - `navigateTo('product-category-detail', { id, title/name, mode: 'view' | 'edit' })`
- 页面内移除 `modalMode === 'view' | 'edit'` 的 `DetailModal` 逻辑。
- “新增类别”处理建议：
  - 方案A（本轮优先）：保留弹框新增，降低改动风险。
  - 方案B（后续可选）：支持 `product-category-detail` 的 `mode:'add'` 页面化新增。

### 3.6 类型与参数约定（涉及 `src/pages/*.tsx`）
- 统一详情参数结构：
  - `id: string`（必填）
  - `mode?: 'view' | 'edit'`（默认 `view`）
  - `name?: string`（用于 tab 标题优化，可选）
- 新页面组件 props 与项目现有约定保持一致：
  - `viewParams?: any`
  - `navigateTo?: (view: string, params?: any) => void`
  - `goBack?: () => void`

## 四、Assumptions & Decisions
- 决策已锁定：
  - 仅改产品资料与产品类别两个模块。
  - 详情采用系统内新标签页，不使用浏览器新窗口。
  - 查看和编辑均页面化。
  - 产品详情字段沿用现有全字段，不做裁剪。
- 假设：
  - `viewParams.id` 始终传递数据库记录主键（字符串化整型），可用于详情查询。
  - 页面化后仍沿用现有保存接口，不需要新增 SQL 迁移。
- 兼容性：
  - 不改动数据库结构，不涉及 `new_version/migrations` 新增 SQL。

## 五、Verification Steps

### 5.1 手工验证（主流程）
1. 在“产品资料”列表点击物料编号/详情，确认打开新 Tab（`product-detail`），不出现弹框。
2. 在产品详情页点击编辑，修改字段并保存，返回列表验证数据已更新。
3. 刷新产品详情页（保留 `id` 参数）后仍能正确加载单条记录。
4. 在“产品类别”列表点击查看，确认打开新 Tab（`product-category-detail`），不出现弹框。
5. 在类别详情页切换编辑并保存，返回类别列表验证数据更新。
6. 同时打开多个不同产品/类别详情，确认顶部 tab key 按 `view:id` 区分，不互相覆盖。

### 5.2 回归验证（受影响点）
1. 产品删除、类别删除原流程可用。
2. 产品系列/产品品类页面行为不变。
3. 现有 `Products` 的筛选、分类树、滚动加载不受影响。

### 5.3 代码质量验证
1. 执行 TypeScript 检查与构建（如 `npm run build`）。
2. 使用 IDE 诊断检查新增页面与改造文件无类型错误。
