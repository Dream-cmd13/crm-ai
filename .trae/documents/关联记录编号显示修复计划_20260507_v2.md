# 关联记录编号显示修复计划

## Summary
- 目标：将“询盘池、线索池、商机池、项目管理”中关联记录展示由数据库 `id` 统一为业务编号（询盘编号/线索编号/商机编号）。
- 范围：按你确认的“全覆盖”，包含列表页、详情页、编辑弹窗。
- 回退策略：查不到编号时回退显示原 `id`，保证可追溯与可跳转。
- 约束：仅改展示层与映射查询；底层保存仍使用关联 `id` 外键，不改表结构。

## Current State Analysis
- 已定位核心页面与组件：
  - `src/pages/Inquiries.tsx`
  - `src/pages/Leads.tsx`
  - `src/pages/Opportunities.tsx`
  - `src/pages/Projects.tsx`
  - `src/components/projects/ProjectDetail.tsx`
  - `src/components/projects/RelatedRecords.tsx`
- 现状结论（基于仓库当前代码）：
  - `Inquiries`：存在 `associatedLead` 显示映射函数与下拉选项能力。
  - `Leads`：详情中的“关联询盘”已接入编号显示函数。
  - `Opportunities`：详情“关联线索/关联询盘”与编辑字段（下拉）已存在编号映射结构。
  - `Projects/RelatedRecords`：组件支持 `inquiryDisplay/leadDisplay/opportunityDisplay` 显示入参。
- 风险点：
  - 仓库当前“部分已改”状态下，可能存在遗漏点（例如某些列表列、弹窗字段或跳转文案未统一），需要做一次全量核对与补齐。

## Proposed Changes

### 1) 统一映射与回退规则（所有模块一致）
- 显示规则：
  - 优先显示业务编号（`inquiry_no`/`lead_no`/`opportunity_no`）。
  - 缺失时回退显示原 `id`。
- 跳转规则：
  - `navigateTo` 参数保持传递原 `id`，不改既有导航协议。
- 查询规则：
  - 使用 Supabase 读取映射表字段：
    - `crm_inquiry(id, inquiry_no)`
    - `crm_lead(id, lead_no)`
    - `crm_opportunity(id, opportunity_no)`
  - 页面级缓存 `Record<string, string>` 映射，避免重复逐条查询。

### 2) `src/pages/Inquiries.tsx`（询盘池）
- 核对并确保：
  - 列表“关联线索”列显示 `leadNo`（回退 `id`）。
  - 详情“关联线索”按钮文本显示 `leadNo`（回退 `id`）。
  - 编辑弹窗字段 `associatedLead` 使用 `select`，`label` 为线索编号、`value` 为线索 `id`。
- 若存在漏点（旧代码直接展示 `associatedLead`），统一替换为映射函数。

### 3) `src/pages/Leads.tsx`（线索池）
- 核对并确保：
  - 详情“关联询盘”显示 `inquiryNo`（回退 `id`）。
  - 跳转仍使用 `selectedLead.inquiryId`。
- 说明：
  - 若无“关联询盘”编辑字段，不强行新增录入能力，只保证既有展示点正确。

### 4) `src/pages/Opportunities.tsx`（商机池）
- 核对并确保：
  - 详情“关联线索/关联询盘”显示编号（缺失回退 `id`）。
  - 编辑弹窗 `leadId/inquiryId` 为 `select`，选项文案显示编号，保存值仍为 `id`。
  - 列表中若存在关联字段展示，也统一为编号优先。

### 5) `src/pages/Projects.tsx` + `src/components/projects/ProjectDetail.tsx` + `src/components/projects/RelatedRecords.tsx`（项目管理）
- 核对并确保：
  - `Projects` 针对 `selectedProject` 的 `inquiryId/leadId/opportunityId` 拉取对应编号并构建 display 值。
  - `ProjectDetail` 正确透传 `relatedInquiryDisplay/relatedLeadDisplay/relatedOpportunityDisplay`。
  - `RelatedRecords` 展示 display 文案，点击跳转继续使用原 `id`。

## Assumptions & Decisions
- 决策：显示编号是 UI 诉求，不改变数据库外键存储模型。
- 决策：所有关联跳转继续传 `id`，确保与现有页面打开逻辑兼容。
- 决策：编号缺失统一回退显示 `id`，不显示“已失效”文案。
- 假设：当前数据库编号字段命名稳定为 `inquiry_no/lead_no/opportunity_no`。

## Verification Steps
- 功能验收（逐页）：
  - 询盘池：列表“关联线索”、详情“关联线索”、编辑弹窗“关联线索”均显示线索编号。
  - 线索池：详情“关联询盘”显示询盘编号。
  - 商机池：详情“关联线索/关联询盘”显示编号；编辑弹窗下拉显示编号。
  - 项目管理：`RelatedRecords` 中“关联询盘/关联线索/关联商机”显示对应编号。
- 回退验收：
  - 人工构造一条关联 `id` 无对应编号数据，确认页面显示回退为 `id`。
- 质量检查：
  - 对上述改动文件执行 TypeScript diagnostics，确认无新增错误。
