# 产品中心新增「规格组」模块计划（基于 public_property_name）

## Summary
- 在左侧「产品中心」新增菜单「规格组」
- 新增页面：对 `public_property_name`（公共属性名称表）做列表查询 + 新增/编辑/查看/删除
- “启用/禁用”统一绑定 `is_searchable`（是否参与搜索）字段
- 页面字段不强制对齐截图里的额外列（筛选类型/筛选目标/排序等），截图仅参考布局与风格

- 数据库已存在表：
  - `public_property_name`：`specification_name`、`group_name`、`image`、`is_searchable`、`created_at`、`updated_at`
  - 相关种子数据已在 [seed.sql](file:///Users/hvai/trae/crm-ai-v3.8/supabase/rebuild/seed.sql) 中提供
- 前端已具备“产品中心”主数据类页面的通用模式：
  - 页面文件位于 `src/pages/`（如 [Brands.tsx](file:///Users/hvai/trae/crm-ai-v3.8/src/pages/Brands.tsx)、[Groups.tsx](file:///Users/hvai/trae/crm-ai-v3.8/src/pages/Groups.tsx)）
  - 数据访问统一封装在 [productRepository.ts](file:///Users/hvai/trae/crm-ai-v3.8/src/lib/productRepository.ts)
  - 新增/编辑弹窗使用 [DetailModal](file:///Users/hvai/trae/crm-ai-v3.8/src/components/DetailModal.tsx)
- 当前尚无 `public_property_name` 对应的类型定义、仓库方法与页面入口

## Proposed Changes

### 1) 类型补齐（前端）
- 修改 [product.ts](file:///Users/hvai/trae/crm-ai-v3.8/src/types/product.ts)
  - 新增接口（命名建议）：
    - `PublicPropertyName`（页面名称为“规格组”，但数据实体仍与表结构一致）
  - 字段建议（camelCase 对齐现有类型风格）：
    - `id: string`
    - `specificationName: string`
    - `groupName?: string`
    - `image?: string`
    - `isSearchable: number`（1/0）
    - `createDate?: string`（映射 `created_at`）
    - `updateDate?: string`（映射 `updated_at`）

### 2) 仓库层新增 CRUD（Supabase）
- 修改 [productRepository.ts](file:///Users/hvai/trae/crm-ai-v3.8/src/lib/productRepository.ts)
  - 新增映射函数：
    - `mapDbPublicPropertyNameToUi(row)`
    - `mapUiPublicPropertyNameToDb(payload)`
  - 新增查询/保存/删除方法（命名建议）：
    - `fetchPublicPropertyNameListFromSupabase(filters)`
      - 支持分页：`page`、`pageSize`（沿用 Brands 的 `PagedResult<T>` 结构）
      - 支持筛选：
        - 关键词：匹配 `specification_name`（ilike）
        - 分组名称：匹配 `group_name`（可选，ilike）
        - 是否参与搜索：`is_searchable`（可选：全部/1/0）
    - `savePublicPropertyNameToSupabase(row: PublicPropertyName)`
      - 新增：insert（不传 id）
      - 编辑：update by id
      - `updated_at` 由触发器/或前端写入（与现有模式一致，建议前端显式写 `updated_at: new Date().toISOString()`）
    - `deletePublicPropertyNameFromSupabase(id: string)`
  - 约束与校验：
    - `id` 使用 `toNullableInt` 校验（复用现有工具函数）
    - `specificationName` 必填且 trim 后不能为空
    - `groupName`、`image` 允许为空（写入 null）

### 3) 新增页面：产品中心 > 规格组
- 新增文件：`src/pages/SpecGroups.tsx`（页面组件名建议 `SpecGroupsPage`）
  - UI结构参考现有主数据页（如 Brands）：
    - 顶部标题：规格组
    - 右上角按钮：新增
    - 筛选区：
      - 规格名称（关键词输入）
      - 状态（下拉：全部/参与搜索/不参与搜索）
      - 分组名称（输入或下拉；本期建议输入，避免额外 distinct 查询）
      - 操作：搜索 / 清空筛选
    - 列表区（表格列建议）：
      - ID
      - 规格名称（specificationName）
      - 分组名称（groupName）
      - 是否参与搜索（isSearchable：显示“是/否”，可做成徽标或开关；本期不强制列表内直接切换，编辑时可修改）
      - 图片（image：缩略图/无则“-”）
      - 创建时间（createDate）
      - 更新时间（updateDate）
      - 操作（查看/编辑/删除）
    - 弹窗（DetailModal）字段建议：
      - 规格名称（必填）
      - 分组名称
      - 图片（URL 文本）
      - 是否参与搜索（select：1=是，0=否）
  - 交互提示：
    - 加载失败 toast.error
    - 保存成功 toast.success
    - 删除成功 toast.success

## Assumptions & Decisions
- 不新增/修改数据库字段；仅使用现有 `public_property_name` 表字段完成“规格组”功能

- 当前项目主应用为 React + TypeScript（尽管偏好为 PHP，本次功能会沿用现有前端代码栈与模式）
